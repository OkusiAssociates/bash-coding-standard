## BCS Compliance Findings — `examples/lib/file/cln/cln`

**BCS1005** (Tier: core) — **[ERROR]** — Line 215
`find "${symbolic[@]}" "$path" -maxdepth ...` passes `"$path"` as a pathname operand without a preceding `--` guard. A directory literally named e.g. `-rf` or `-P` supplied on the command line (or as the default via a symlink attack) would be parsed by `find` as an option rather than a path. BCS1005 requires `--` before any pathname operand originating from variables/user input. Fix: `find "${symbolic[@]}" -- "$path" -maxdepth "$max_depth" ...` (GNU findutils accepts `--` to end option parsing).

**BCS0806** (Tier: recommended) — **[WARN]** — Line 169
`-P|-N|--no-prompt)` reassigns two standard option letters (`-P` is standard for `--prefix`, `-N` is standard for `--not-dry-run`) to an unrelated `--no-prompt` purpose. The `#bcscheck disable=BCS0806` directive on line 166 only suppresses the *next* clause (`-p|-n|--prompt`, lines 167–168); this is a separate, subsequent `case` clause and is not covered by that suppression. Fix: choose non-conflicting letters for the "no-prompt" toggle, or move/duplicate the suppression directive to cover this clause as well if the reuse is intentional.

**BCS0802** (Tier: style) — **[WARN]** — Line 174
`printf '%s\n' "$SCRIPT_NAME" "$VERSION"` recycles the one-conversion format string across its two arguments, producing two output lines (`cln\n1.1.0\n`) instead of the canonical single-line `scriptname X.Y.Z` format. Fix: `printf '%s %s\n' "$SCRIPT_NAME" "$VERSION"` or `echo "$SCRIPT_NAME $VERSION"`.
